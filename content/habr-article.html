﻿Как заставить open-source агентную среду понимать русскую речь, не отправляя ни секунды аудио в облако.

Проблема

DeepSeek Harness (DSH) — открытая агентная среда: терминал, файлы, плагины, модель. В интерфейсе есть кнопка микрофона, и она честно работает — но только для китайского, английского, японского, корейского и кантонского. Внутри стоит SenseVoice, и русского в его языковом наборе нет вообще.

На практике это выглядит так. Говоришь по-русски — получаешь «As a piece goes through.» или латинскую бессмыслицу. Не потому, что плохой микрофон, а потому что модель определила язык как английский.

Задача звучала просто: пусть кнопка понимает русский. Ограничения я поставил себе сразу:

  • локально, без облака и API-ключей;
  • без отдельного приложения — та же кнопка, тот же интерфейс;
  • установка одной строкой, без ручной сборки Python-окружения.

Как устроен голосовой ввод в DSH

В DSH есть сервис speechToText — реестр провайдеров распознавания. Клиентская часть не знает, кто именно распознаёт: она записывает WAV, отдаёт байты провайдеру и вставляет вернувшийся текст в поле ввода.

Интерфейс провайдера минимальный:

{
  info: { id, name, location: 'host-local', languages: [...] },
  transcribe({ audio, language }, signal) -> { text, audioSeconds, inferenceSeconds }
}

То есть всё, что нужно, — зарегистрировать свой провайдер и вернуть текст. Интерфейс, кнопка, настройки и хранение выбранного языка уже есть. Это сильно упрощает жизнь: плагин не рисует UI, он подменяет движок.

Под это описание идеально ложится Whisper: MIT-лицензия на код и веса, около сотни языков, отличный русский, работает на CPU.

Провайдер на Whisper

Плагин называет себя EchoRUS. Внутри — три части:

  1. index.js — регистрация провайдера echorus-local, поиск Python, установка зависимостей, скачивание модели.
  2. python/echorus_stt.py — один вызов распознавания: WAV на входе, JSON на выходе.
  3. cordis.patch.yml — строка плагина и выбор провайдера по умолчанию.

Распознавание — это faster-whisper поверх CTranslate2, модель large-v3-turbo в int8.

const model = new WhisperModel(modelPath, { device: 'cpu', compute_type: 'int8' })
const segments = model.transcribe(wav, { language: 'ru', beam_size: 5, vad_filter: true })

Установка без боли

Первая версия плагина работала только у меня: абсолютные пути к питону и папке с моделью. Для чужой машины это негодно, поэтому появился bootstrap:

  1. Поиск Python. Переменная ECHORUS_PYTHON, затем python3/python из PATH, затем стандартные места установки. Проверяется версия — нужна 3.9+.
  2. Установка пакетов. pip install --target в каталог данных плагина. Без виртуального окружения: venv на Windows регулярно спотыкается на ensurepip, а --target работает всегда.
  3. Скачивание модели в обычную папку, а не в кэш Hugging Face.

Всё это оформлено как «подготовка» — штатный механизм DSH, который показывает прогресс в панели голосового ввода. Пользователь видит, что происходит, и может отменить.

Что не сработало

Две проблемы стоили вечера.

Первая: скачивание висело. Модель на 1,5 ГБ стартовала и замирала на 3,6 МБ. Процесс живой, CPU тикает, байты не идут. Причина — транспорт Xet у Hugging Face: на некоторых сетях он не поднимается и молча ждёт. Лечится одной переменной HF_HUB_DISABLE_XET=1, после чего те же 1,5 ГБ скачались за 159 секунд.

Вторая: модель занимала вдвое больше. Кэш Hugging Face по умолчанию раскладывает файлы через симлинки, а на Windows без режима разработчика симлинков нет — и кэш физически дублирует веса. 3 ГБ вместо 1,5. Скачивание в обычную папку снимает вопрос.

Заодно выяснилось, что проверка кэша при каждом запуске тоже ходит в сеть и снова упирается в Xet. Пришлось ставить HF_HUB_OFFLINE=1 на этап распознавания: модель уже на диске, сеть не нужна.

Замеры

Железо: обычный ноутбужный CPU, без GPU.

Модель Загрузка Распознавание 29 с аудио RTF Русский
large-v3-turbo 3,3 с 5,8 с 0,20 алфавит распознан
large-v3 4,8 с 13,4 с 0,47 «абабагады южзы»

Вывод, который меня удивил: более крупная модель хуже. На неразборчивом фрагменте large-v3 уверенно сочиняет связный текст, а large-v3-turbo честно выдаёт структуру. Скорость отличается втрое. По умолчанию стоит turbo.

Живая диктовка: 16 секунд речи — 8,4 секунды до текста, включая загрузку модели.

Имена собственные

Отдельная боль — названия. «Кубернетес», «Постгрес», «Графана» в русской речи звучат по-русски, и модель пишет их кириллицей. Хочется латиницу.

Первый подход — глоссарий (hotwords в faster-whisper): подаём модели список терминов. Имена встали правильно (Kubernetes, PostgreSQL), но пропала вся пунктуация — модель перестала ставить точки и запятые.

Второй подход — контекстная подсказка (initial_prompt): «Это деловая диктовка на русском языке. Пиши с пунктуацией и заглавными буквами». Результат лучше: и пунктуация, и заглавные, и PostgreSQL.

Третий, самый надёжный — словарь подстановок уже после распознавания:

replacements: Кубернетес=Kubernetes, Постгрес=PostgreSQL, Нжинкс=Nginx

Замена по целым словам, регистр не важен: «кубернетес» и «Кубернетес» станут Kubernetes. Падежные формы («Кубернетеса») намеренно не трогаются — иначе получилось бы Kubernetesа, смесь алфавитов.

Вывод: не надо учить модель определять язык каждого слова. Надо детерминированно подставлять написание.

Что в итоге ставится по умолчанию

  • Модель large-v3-turbo, язык ru, CPU, int8.
  • Контекстная подсказка про деловую диктовку с пунктуацией.
  • Пустой глоссарий и пустой словарь подстановок — каждый добавляет свои термины.

Приватность

Аудио пишется браузером, передаётся локальному процессу, распознаётся локально и удаляется сразу после расшифровки. Наружу уходят только запросы на скачивание пакетов и модели при первой установке. Дальше распознавание работает офлайн — можно выключить сеть и проверить.

Ограничения

  • Только CPU. GPU не используется, хотя faster-whisper его умеет.
  • Модель загружается на каждый запрос: плюс 3–4 секунды к каждой фразе. Постоянный воркер это уберёт, но его пока нет.
  • Первая установка — около 2 ГБ и несколько минут.
  • Нет разделения по говорящим и ручной правки пунктуации.
